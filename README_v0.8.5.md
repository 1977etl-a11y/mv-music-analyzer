# MV Music Analyzer v0.8.5

採用済みのv0.8.4改稿案を、元CUTの一致と制作者の最終確認後に、元コンテの複製へフィールド単位で反映します。比較・解析・基準保存には変更を加えません。

## スマホの操作
1. 「改稿案の適用前チェック」で改稿案JSONを読み込むか「画面の改稿案を使用」を押します。画面の案はその時点のコピーです。編集を続けた場合は再取得してください。
2. 上のコンテ読み込みで選択済みの元データを利用します。別途この欄で元コンテを指定した場合はそのファイルを優先し、画面にも表示します。
3. CUTごとの変更前後、不一致、警告を確認します。前後CUTと改稿案の明示条件は折りたたみ欄で参照できます。
4. 「改稿内容を確定」と、元コンテの確認、時刻・動作・人物・小道具・衣装・カメラの項目別確認を行います。初期状態はすべて未確認です。「再検討」「未定」「仮」は警告候補であり、確定性を機械で断定しません。制作指示が未完成なら改稿案作成へ戻ってください。
5. 適用できないCUTがある場合、既定は全件保留です。「適用可能なCUTだけを出力する」を明示的に選べます。停止理由と未確認事項はCUTごとに表示します。
6. 適用可能なCUTと変更フィールドを最終確認し、「確認済み変更で改訂版を生成」を押します。
7. 「改訂版コンテJSONを書き出す」と「適用履歴JSONを書き出す」をそれぞれ押してください。ページ更新前に保存してください。

採用対象0件は正常で、架空の改訂版は生成しません。確認状態と生成結果はメモリ上のみです。入力の切り替えや再取得は確認をリセットします。

## 照合・適用ルール
- CUTの識別子は既存の id、なければ cut を使用します。表示番号や配列位置で代用しません。重複は停止します。
- original_cutと対象CUTは全項目を照合します。JSONオブジェクトのキー順は無視し、配列順・値・項目の有無は比較します。
- 改稿案にある元コンテのid/title/version/CUT数は、取得できるものを照合します。識別情報がない入力ではコンテ全体の同一性を保証できないため、対象CUTの完全一致に加えて制作者による元ファイル確認を必須にします。
- draft_changesを信用するだけでなくoriginal_cutとdraft_cutから再計算して一致確認します。確認済み変更フィールドだけを複製へ反映します。
- 識別子・参照ID・CUT番号の変更、フィールド追加／削除、型や構造変更は安全のため適用を停止します。v0.8.4の既存スカラー項目の編集を対象とします。
- CUTの数値時刻が不足する場合、負値や逆転がある場合は停止します。前後の空白・重複は意図的な場合があるため警告と制作者確認に分けます。
- 人物・小道具・衣装・カメラ等の意味的な整合は自動判定しません。元の確認状態・未確認事項を表示し、制作者による適用時の再確認を要求します。既存の確認済みフラグだけでは通過しません。
- 元CUTに解析イベントの時刻差を自動適用しません。元コンテ、改稿案、基準には書き込みません。

## 出力
コンテ本体: mv_storyboard_revised_v0_8_5.json
元が配列なら配列、cutsを持つオブジェクトならその形式を維持します。CUT数、順序、未変更項目、参照情報を保持します。本体に履歴や新スキーマを混在させません。

履歴: mv_storyboard_revision_application_v0_8_5.json
schema: mv_storyboard_revision_application.v0.8.5 / version: 0.8.5
source_proposalに元改稿案の識別情報と内容フィンガープリント、baseline_saved_atに基準保存日時を保持します。original_storyboard_fingerprint/revised_storyboard_fingerprintで対象を関連付け、appliedにCUT・変更前後・制作者チェック・警告、heldに保留CUTと理由、final_confirmationに最終確認と部分適用方針を保存します。フィンガープリントは既存stableId方式であり暗号学的保証ではありません。

## 検証の範囲
合成44 CUTで要求A〜F、元データ不変、43 CUT保持、配列／オブジェクト形式、改訂版の既存読み込み、重複ID、改変された変更一覧、参照編集の停止、部分適用を検証します。実44 CUTと実際のCUT 02改稿案はこの作業環境に存在せず、合成の「右踵二打のタイミングを再検討」を使用します。実スマートフォン・実コンテの意味的整合は未検証です。
