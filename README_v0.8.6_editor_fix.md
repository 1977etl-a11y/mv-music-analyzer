# v0.8.6 保存済み改稿案の編集導線修正

## 操作名と手順
1. 「改稿案作成」の「保存済みv0.8.4改稿案JSONを編集」から保存済みファイルを読み込みます。v0.8.3からの作り直しは不要です。
2. 「CUTを選択」でCUT 02を選び、「改稿案を編集」の動作等を編集します。保存済みファイルの場合は保存されたdraft_cutの値を表示します。「改稿内容・補足」「改稿理由／維持する理由」、6種類の確認状態・メモも復元します。
3. 「前後CUTとの整合確認」で確認します。復元できない項目は未確認。値を編集した場合は再確認が必要な理由を表示し、メモを保持します。前後情報の更新で情報が変わらなければ確認状態は維持します。
4. 「編集した改稿案を適用前チェックへ渡す」を押します。自動適用はしません。元CUT・前後CUTが一致し、明示的に「整合を確認」とされた項目を引き継ぎます。一致確認できない場合は状態・メモを保持して、適用側で再確認が必要な理由を示します。
5. 「今回の適用を妨げている項目」の「CUT 02の編集・確認へ戻る」から対象CUTへ戻れます。確認項目を特定できる場合は該当の選択欄へ移動します。編集中データと異なる案への切り替えでは破棄確認を表示し、無断で置き換えません。
6. 内容確定・元コンテ確認・関連指摘への判断を行い、最終承認後に改訂版を生成します。「改訂版コンテJSONを書き出す」で別ファイルに保存します。

## 保持と安全性
original_cut、draft_cut、review_entries、改稿内容・理由、前後CUT情報、認識可能な確認状態・メモ、その他の入力フィールドをコピーして保持します。確認状態の欠損・不明な値や復元できない前後情報は確認済みと推定しません。draft_changesの不整合は勝手に修復せず、既存の適用時照合で停止します。

編集中の変更は適用側へ自動同期しません。古い案の生成・書き出しを無効にし、明示的な再引き渡しを要求します。引き渡し時には最終承認を解除します。同一の内容・確認情報の再引き渡しで、既存の個別確認を理由なく消しません。変更された案では内容確定・関連指摘の再確認が必要です。対象元データが同じ場合の元コンテ確認は保持します。

作成画面の確認状態を引き継いでも、元コンテ一致、必要な解析・前後CUT、変更関連の指摘、内容確定、最終承認の判定は省略しません。全体567件の既存指摘を停止条件へ戻していません。

入力のコンテ・解析・基準・改稿案ファイルには書き込みません。解析の+0.3秒を自動適用しません。改稿案と改訂版は従来のJSON形式です。アプリ表示はv0.8.6のまま、Service Workerキャッシュをv0.8.6-editor-1へ更新します。

## 検証・制約
合成44 CUT・567件の既存指摘を使ったブラウザ往復、CUT 02以外の不変、比較基準の不変、未確認状態・最終承認、欠損復元、メモ保持、元データ不変を回帰テストで確認します。実44 CUT・実スマートフォンは未検証です。編集はメモリ上に保持されるため、ページ更新前に「改稿案JSONを書き出す」で保存してください。
