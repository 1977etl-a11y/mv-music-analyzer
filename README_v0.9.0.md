# v0.9.0 制作者によるフィールド変更の登録

## 判断記録と実変更を分離
revision_summary / reason / continuity.author_checksは判断・確認記録のまま保持します。アプリは文章を解釈・転記せず、解析イベントの時間差も適用しません。
「コンテ本体へ反映する変更」で既存フィールドを選び、現在値を確認し、制作者が入力した改訂値を登録します。未登録の候補はproposalにも完成コンテにも書き出されません。登録済みの改訂値と同値なら差分・確認状態は変わりません。元値へ戻した場合、そのフィールドの差分は消え、整合確認は再確認になります。

## 操作
1. 保存済みv0.8.4改稿案を開き、読み込み済み元コンテを使用する。
2. 「コンテ本体へ反映する変更」でactionなどの既存フィールドを選ぶ。
3. 「現在値（元コンテ）」と「改訂値」を確認し、「選択フィールドをdraft_changesへ登録」を押す。
4. 別CUTは「隣接CUTへの変更候補」を開く。元の値が初期表示され、文章の候補は生成しない。編集後「CUT 03へ反映（draft_changesへ登録）」を明示操作する。この時点では完成コンテは変更されない。
5. 新規対象CUTは「未判断」、6項目は「未確認」。登録により接続に関係する既存対象CUTの6項目も未確認へ戻る。メモは残す。「前後CUTとの整合確認」には隣接CUTの登録済み改稿案も表示する。
6. 各CUTの採否・理由・整合確認を行い「編集した改稿案を適用前チェックへ渡す」。照合と最終承認後、改訂版を別ファイルに書き出す。

従来の直接編集も「既存フィールドを直接編集（入力を差分へ登録）」として残す。入力は従来どおり実変更になる。判断記録だけに残す場合は「改稿内容・補足」や確認メモのみ編集する。

## JSON互換性
proposalスキーマはmv_storyboard_revision_proposal.v0.8.4を維持する。変更のCUTはtargets[].cut_idで特定し、各targetのdraft_changesに従来どおりpath/before/afterを格納する。横断配列やcutキーの追加による適用エンジンの再設計は行わない。

例（抜粋）:
```json
{"targets":[
  {"cut_id":"02","draft_changes":[{"path":["action"],"before":"元の動作","after":"制作者が編集した動作"}]},
  {"cut_id":"03","promotion_origin":{"kind":"author_selected_neighbor","source_cut_id":"02"},"draft_changes":[{"path":["action"],"before":"元の開始状態","after":"制作者が編集した開始状態"}]}
]}
```
promotion_originは隣接CUTを明示登録した経路だけを記録する追加情報。original_cut/draft_cut/review_entries/判断/確認は既存形式。新規対象へ元CUTの確認や解析根拠をコピーしない。
完成コンテのschema・配列/オブジェクト形式は元データを維持。適用履歴スキーマはv0.8.5、application_versionは0.9.0。出力名はmv_storyboard_revised_v0_9_0.jsonとmv_storyboard_revision_application_v0_9_0.json。proposal出力名は互換性維持のため従来名。

## 安全性・制約
適用エンジンの照合・判定・変更反映処理は変更していない。読み込み済み元コンテ取得のread-only getterとバージョンのみ追加・更新。登録対象は既存の文字列・数値・booleanの末端フィールド。識別子・参照・補助情報、項目追加削除・構造変更は対象外。
隣接CUTを新規登録するには元コンテが必要。保存時の元CUT/前後CUTが照合できなければ登録を止める。欠損した前後情報は推測しない。
元コンテ・解析・baselineは変更しない。元コンテをdeep copyし、確認済みの変更フィールドだけを反映する。二打時刻2.3917/2.7748秒を維持し、検証用2.6917秒は採用しない。

## テスト
A〜Lの合成44 CUT回帰、v0.8.8の出力検証、既存211参照比較を維持。実際のユーザーの44 CUTファイルは作業環境にないため、提供文言を用いた合成データと区別する。実機スマートフォンは未検証。Edgeの320/390px画面で候補の未反映、明示登録、新規CUT確認、最終承認、44 CUTのダウンロードを検証する。

検証結果：Node全123テスト成功、既存JSONスキーマ3件成功。隔離Edge 154で320/390px操作、オフライン再読込、明示登録後の2 CUT / 2 action差分のみのダウンロードを確認。
