# MV Music Analyzer v0.8.6

## 調査結果と変更
v0.8.5の「44 CUT／要確認44 CUT／指摘…件」は通常検証の全体集計であり、適用判定へ直接渡されていませんでした。通常検証の表示名を明確にし、適用前チェック側に独立した変更前後の検証と分類を追加しました。通常検証器、比較・基準保存のロジックは変更していません。

- 元コンテの既存指摘：全CUTを元のまま検証した結果。全件を折りたたみ表示します。件数は停止件数ではありません。
- 今回の変更に関係する既存指摘：改稿後にも残る既存指摘のうち、変更フィールドと依存CUTに関係するもの。既存指摘の内数です。
- 今回の変更で新たに生じた指摘：同じ解析JSON・同じ検証器で変更前後を比較し、新規に出現または内容が変わった指摘。コード・CUT・参照ID・重大度・理由を比較し、同一指摘の重複件数も扱います。消えた既存指摘は関連指摘の停止対象にしません。

## 適用範囲
変更フィールド、対象CUT、元コンテの明示的接続先（なければ配列順の前後CUT）を記録します。時刻・動作変更ではCUT 01→02→03の境界・連続性を確認します。時刻移動で離れたCUTとの重複が新たに生じた場合も対象です。

時刻変更では参照時刻・使用範囲・音源尺も対象です。動作・カメラ等の変更で参照用途がaction/camera/sync等を明示する場合も解析参照を確認します。無関係な他CUTの参照不足や全体メタデータ不足だけでは停止しません。解析の参照索引や必要な参照値がない場合、対象・依存CUTの不正時刻、接続先を特定できない場合は機械的に停止します。全体の形式不正で検証器が実行できない場合も、確認できない理由を表示して停止します。

数値では判断できない動作・人物・小道具・衣装・カメラの整合は制作者確認です。確認済みへ自動変更しません。意図的な空白や重複など警告がある場合には「今回の変更に関係する指摘・新規指摘を確認」の操作も必要です。必要なデータの欠損やエラーはこのチェックで解除できません。

## 操作
1. 元コンテと改稿案を読み込みます。必要な解析JSONは従来の「解析JSON」欄から読み込みます。
2. 「今回の適用を妨げている項目」を確認します。全体の既存指摘とは別に、対象CUTと次の確認内容を表示します。
3. 3種類の指摘欄と変更前後・前後CUTの情報を確認します。
4. 各必須確認と最終確認後、従来どおり元データの複製へ変更フィールドだけを反映し、別ファイルへ書き出します。

部分適用で、保留CUTを除いた結果の接続条件・指摘が変化する場合は生成を停止します。対象を絞った改稿案で再確認してください。解析JSONの変更時も確認状態と生成結果をリセットします。

## 互換性・出力
入力は引き続きv0.8.4改稿案JSON。改訂版は元コンテの配列／オブジェクト形式を維持します。出力名はmv_storyboard_revised_v0_8_6.jsonとmv_storyboard_revision_application_v0_8_6.json。履歴スキーマmv_storyboard_revision_application.v0.8.5は維持し、application_version: 0.8.6とvalidation_scopeを追加します。元コンテ、解析、保存済み基準には書き込みません。

## テスト・制約
合成44 CUT、500件超の既存指摘を持つデータで、CUT 02だけの変更とCUT 01・03の確認を検証します。実際の567件の入力ファイルは作業環境になく、同じ567件の内容を再現したとは主張しません。意味的な整合は自動判定できません。フィールド名・参照用途による依存関係は保守的な規則であり、制作者確認を代替しません。実スマートフォンでの検証は未実施です。
