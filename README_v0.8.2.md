# MV Music Analyzer v0.8.2 — 影響CUTレビュー

既存の比較結果 `event_changes` をCUT単位に表示する独立したレビュー機能です。解析計算、差分検出、比較基準の保存形式・保存処理、通常検証は変更していません。解析・コンテ・基準のスキーマと保存名も従来どおりです。`storyboard_metadata_issues` と `analysis_comparison.issues` の分離も維持します。

## スマホでの操作

1. 「コンテ参照・検証」で現在の解析JSONとコンテを読み込み、「保存済み基準と比較」を押します。既存基準の再作成は不要です。
2. 「影響CUTレビュー」に変更イベントの影響先だけが表示されます。同じCUTの複数イベントは一つのカードに集約します。
3. イベントID、フィールドの変更前後、開始・終了時刻の移動量を確認します。「参照している演出項目」を開くと、そのイベントへの用途・演出関係・写像と、CUTに記載された動作・カメラ情報を読めます。
4. 未判断／確認済み／要修正／変更不要をCUTごとに選択します。動作開始・カメラ切り替え・音響同期等は確認候補であり、修正必須の判定ではありません。
5. 「レビューJSONを書き出す」で判断を保存します。従来の長い比較結果は「比較結果JSONを表示」から開けます。

判断は画面内で保持されます。同一内容の比較を再実行しても判断を維持します。比較対象や変更内容が変わった場合は以前の判断を引き継ぎません。入力切り替え中は古いレビューを非表示にし、再比較を待ちます。ページ更新前に書き出してください。レビューJSONの再インポートや端末内への永続保存は今回の対象外です。

## レビューJSON

ファイル名：`mv_impact_cut_review_v0_8_2.json`。元コンテ・解析・比較基準とは別ファイルです。

- `schema`: `mv_impact_cut_review.v0.8.2`
- `review_id`: 基準保存日時・比較状態・レビュー対象と変更内容から導出した再現可能なID。作者の判断変更では変えません。
- `baseline_saved_at`: 使用した基準の保存日時。
- `comparison`: 解析比較状態、参照ID照合件数、実際の値比較件数、識別情報の差分、比較不能件数、メタデータ指摘。
- `cuts[]`: 変更イベントの影響CUTだけを格納。`cut_id`、`cut_number`、`status`、`events`。
- `status`: `unreviewed`（未判断）、`reviewed`（確認済み）、`needs_revision`（要修正）、`no_change`（変更不要）。作者が選択します。
- `events[]`: `event_id`、`change`、`fields`（変更フィールドと前後値・存在有無）、`time_shifts`（fieldとdelta_sec）、`review_candidates`（任意の確認候補）、`authored_items`（元コンテの参照・演出項目）。
- `policy`: 候補と作者判断の区別、および元データを変更しない方針。

時刻移動はafter−before。正は後、負は前へ移動です。開始と終了は個別に表示します。存在しない前後値から移動量を推定しません。音源条件不一致などでイベント値の比較ができない場合は、その状態を表示し、架空の変更CUTを作りません。CUT本文だけの変更は従来の `cut_changes` に残り、イベント変更のレビューには混ぜません。

具体例：[合成レビューJSON](sample_impact_review_v0_8_2.synthetic.json)。指定テストIDを含みますが、実44CUTコンテの転載ではありません。
